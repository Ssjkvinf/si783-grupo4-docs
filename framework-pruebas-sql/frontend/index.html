¿Qué problema atiende?

Cuando una comprobación SQL sobre Oracle se repite, las consultas, los resultados esperados y las evidencias suelen quedar dispersos, y cuesta comparar con ejecuciones anteriores. Es una necesidad potencial que planteamos; todavía no la hemos medido en una organización.

¿Qué hace?

Ejecuta su consulta, la compara con el resultado que usted indica y guarda la evidencia (consulta, esperado, obtenido, estado y fecha). Cada comprobación termina en PASS, FAIL o ERROR.

¿Para quién es?

Para personas que comprueban bases Oracle, como desarrolladores o analistas de pruebas. Es un prototipo académico: aún no se ha evaluado con una empresa.

Conectar

En Inicio, elija una conexión Oracle y escriba la contraseña del usuario Oracle. Se usa solo para ejecutar y no se guarda.

Decir qué espera

Use el asistente de reglas (sin escribir SQL) o escriba un SELECT, y diga qué resultado espera: un número, sí/no o un valor. La aplicación decide cómo comparar.

Ejecutar y guardar

Verá PASS, FAIL o ERROR con la explicación. Guárdelo como caso, júntelo con otros en una suite y repítalo con un clic cuando quiera.

Palabras clave
PASS
La consulta devolvió lo que usted esperaba.
FAIL
La consulta se ejecutó, pero el resultado no coincide: puede haber un problema en los datos.
ERROR
No se pudo ejecutar o evaluar (tabla inexistente, contraseña incorrecta, sentencia rechazada…).
Caso
Una consulta guardada con su resultado esperado.
Suite
Un grupo de casos que se ejecutan juntos.
Comparación automática
Si espera un número y la consulta calcula un COUNT/SUM, compara ese valor; si es un número y no, compara la cantidad de filas; si es sí/no, comprueba si devuelve filas; si es un texto, compara el valor devuelto.

Qué protege la aplicación
  • TEST: INSERT, UPDATE y DELETE se ejecutan y luego se revierten (rollback).
  • STAGING: igual que TEST, pero pide confirmación antes de ejecutar cambios.
  • PRODUCTION: solo SELECT, con una cuenta Oracle de solo lectura; no se muestran las filas.
  • DROP, ALTER, TRUNCATE, CREATE, GRANT y bloques PL/SQL se rechazan antes de llegar a Oracle.

Límite: el rollback no deshace secuencias (NEXTVAL) ni lo que haga un disparador autónomo. Use siempre un usuario Oracle con los mínimos permisos.

Preguntas frecuentes
¿PASS significa que toda la base está bien?No: solo que la regla que configuró se cumple. Por eso conviene agrupar varias reglas en una suite.
¿Dónde se guarda mi contraseña de Oracle?En ninguna parte: viaja solo en la petición de ejecución y se descarta.
¿Cómo repito una comprobación?Guárdela como caso y añádala a una suite; luego use «Ejecutar suite» o la línea de comandos / GitHub Actions.
¿Puedo cargar muchos casos a la vez?Sí: en «Casos de prueba» descargue la plantilla de Excel, complétela e impórtela (se valida antes de guardar).
Salió ERROR, ¿qué reviso?Abra el detalle en el Historial: verá el mensaje. Lo habitual es una tabla mal escrita, la contraseña o una sentencia no permitida en ese ambiente.

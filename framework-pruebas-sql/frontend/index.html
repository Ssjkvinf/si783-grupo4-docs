Compruebe una consulta SQL en Oracle y conserve la evidencia

Ejecute una comprobación, compárela con lo que usted espera y guarde el resultado para repetirla y revisar fallos.

¿Qué problema atiende?

Cuando una comprobación SQL sobre Oracle se repite, las consultas, los resultados esperados y las evidencias suelen quedar dispersos, y cuesta comparar con ejecuciones anteriores. Es una necesidad potencial que planteamos; todavía no la hemos medido en una organización.

¿Qué hace?

Ejecuta su consulta, la compara con el resultado que usted indica y guarda la evidencia (consulta, esperado, obtenido, estado y fecha). Cada comprobación termina en PASS, FAIL o ERROR.

¿Para quién es?

Para personas que comprueban bases Oracle, como desarrolladores o analistas de pruebas. Es un prototipo académico: aún no se ha evaluado con una empresa.

Primero necesita un proyecto activo para guardar sus comprobaciones.

En este recorrido solo se ejecutan consultas SELECT. Para INSERT, UPDATE o DELETE use «Casos de prueba».

Siguiente paso: configure una vez y repita cuando quiera

Una suite agrupa reglas sobre sus datos (por ejemplo: «hay 5 productos», «no hay productos sin nombre», «existe el producto 3»). Se crea una sola vez y después se ejecuta de nuevo con un clic; cada ejecución queda en el historial. Los ejemplos usan la tabla de demostración FRAMEWORK_TEST_ITEMS y sus datos (ver docs/demostracion-fase2.md).

Solo crea casos y suites en esta aplicación; no modifica Oracle.

Use la conexión y la contraseña del paso 1.

Más herramientas en el menú lateral: guardar y agrupar comprobaciones (Casos y Suites), revisar ejecuciones anteriores (Historial) y administrar proyectos y conexiones.

Guía de Uso Rápido

Para empezar, vaya a Inicio y haga su primera comprobación:

  1. Conectar: elija una conexión Oracle (o cree una) y escriba la contraseña. No se guarda.
  2. Comprobación: elija un ejemplo o escriba un SELECT, e indique qué espera que devuelva.
  3. Ejecutar: verá si pasó (PASS), no coincidió (FAIL) o no pudo evaluarse (ERROR), y por qué.
  4. Después: guárdela como caso de prueba (confirmando usted el valor esperado) o repítala.

Módulos avanzados (menú lateral): Proyectos, Conexiones Oracle, Casos de prueba, Suites (grupos de casos) e Historial de ejecuciones.

Seguridad: las reglas dependen del ambiente de la conexión:
  • TEST: los casos con INSERT, UPDATE o DELETE se ejecutan y luego se revierten (rollback).
  • STAGING: igual que TEST, pero pide confirmación para ejecutar DML.
  • PRODUCTION: solo SELECT, con una cuenta Oracle de solo lectura; no se muestran las filas.
